# Gas Korea

Android-клиент находится в отдельной папке **[android](android/README.md)**. Это нативное приложение Kotlin/Jetpack Compose с тем же API и основными возможностями iOS-клиента. Откройте папку `android` в Android Studio; инструкции по сборке и подключению к серверу — в её README.

iOS-приложение на SwiftUI и сервер Python/SQLite для анонимных комплиментов между друзьями. **Интерфейс приложения, вопросы и сообщения API — на английском.** Этот README — на русском.

Проект остаётся технической альфой: сервер проверяется автоматическими тестами и сценарием через настоящий HTTP, но сборка и работа обновлённого приложения на iPhone ещё не подтверждены. В окружении разработки нет Xcode. Подробности — в [результатах проверок](docs/VALIDATION.md).

## Что теперь реализовано

- Аккаунты с паролями, токены в Keychain, смена пароля, одноразовый резервный код восстановления и управление активными сессиями. Восстановление и смена пароля завершают остальные сессии.
- Каталог школ с постоянными ID, поиском и отдельными записями для одноимённых школ. Есть импорт JSON/CSV и загрузчик официального каталога NEIS. Новая регистрация требует выбора школы из каталога и даты рождения; допускается возраст 14–19 лет.
- Редактирование имени, логина и школы. Смена школы требует пароля и подтверждения: дружеские связи, заявки и приглашение удаляются.
- Поиск друзей по части имени или логина внутри школы, взаимное подтверждение дружбы и приглашения с кодом на семь дней.
- 48 английских вопросов в отдельном JSON-каталоге, из которых сервер выдаёт 12 в день. Для опросов нужны **четыре подтверждённых друга**. Варианты учитывают частоту показа всех друзей, а не только первых в списке.
- Сервер сохраняет набор вопросов, варианты ответа, пропуски и число замен вариантов. Пропущенные вопросы можно вернуть. Замена вариантов подбирает других друзей, когда они доступны; разрешено до трёх замен на вопрос в день.
- Голос и награда в 20 баллов записываются одной транзакцией; повторный запрос не начисляет награду второй раз. Есть журнал баллов. День меняется в полночь по Корее.
- Inbox с поиском, загрузкой следующих страниц и общим счётчиком непрочитанного. Получатель не получает идентификатор отправителя или точное время голосования. Текст старого комплимента сохраняется при изменении каталога вопросов.
- Жалобы, блокировки, просмотр статуса рассмотрения и отмена анонимной блокировки. Оператор может обработать жалобу, приостановить аккаунт и отозвать сессии через CLI.
- Экспорт данных, удаление аккаунта, запись версии принятой информации о приватности. Удаление аккаунта обезличивает доставленные комплименты, сохраняя историю получателя и корректность баланса остальных пользователей.
- Ограниченный офлайн-кэш с защитой файлов iOS, выход с устройства без сети, обновление данных каждые 30 секунд, пока приложение активно. Есть добровольное ежедневное локальное напоминание в 20:00.
- Версионированная миграция базы, резервная копия перед переходом со старой схемы, проверяемые резервные копии, очистка старых данных, шаблоны systemd, агрегированные метрики активности и D1/D7.

Подробное сопоставление с прежними недоработками и оставшиеся ограничения — [docs/STATUS.md](docs/STATUS.md).

## Быстрый запуск сервера

Нужен Python 3.10+ с SQLite и OpenSSL scrypt. Команды выполняются из каталога с этим README:

```sh
python3 server/manage.py init
python3 server/manage.py import-schools server/examples/schools.json
python3 server/app.py
```

Вторая команда добавляет **две явно демонстрационные школы только для локальной проверки**. Она не создаёт аккаунтов или голосов. Для пилота с настоящими школами загрузите проверенный каталог согласно [инструкции развёртывания](docs/DEPLOYMENT.md#school-catalog).

API доступен по `http://127.0.0.1:8080`, база — `data/gas.sqlite3`. `GET /health` возвращает `status: "ok"` и `schemaVersion: 2`. Для режима разработки сторонние Python-пакеты не нужны.

Для подключения iPhone в той же локальной сети:

```sh
GAS_HOST=0.0.0.0 python3 server/app.py
```

В Debug-сборке приложения откройте **Server Settings** и укажите IP компьютера с сервером, например `http://10.12.249.108:8080`, **без `/health`**. IP должен быть из локального диапазона `10.*`, `172.16.*`–`172.31.*` или `192.168.*`. Узнать адрес Linux-компьютера можно командой `hostname -I`. Mac и сервер должны быть доступны друг другу по сети. Имя `.local` и SSH-туннель не требуются.

На симуляторе `localhost` подходит только для сервера на том же Mac; на физическом iPhone он означает сам телефон. Разрешите приложению доступ к локальной сети при запросе. Для внешнего сервера используйте HTTPS. Release-сборка сохраняет прежнее ограничение: HTTP только для localhost и `.local`, локальные IP разрешены исключительно в Debug.

## Запуск симулятора на Mac с сервером на Linux

1. На Linux запустите `GAS_HOST=0.0.0.0 python3 server/app.py` из каталога проекта и оставьте процесс работать.
2. На Mac проверьте `http://IP-СЕРВЕРА:8080/health` в браузере.
3. Перенесите **актуальный проект целиком** на Mac: исходники iOS, `Gas.xcodeproj` и сервер должны соответствовать одной версии. Если локальные коммиты ещё не отправлены в GitHub, `git pull` их не загрузит.
4. Откройте `Gas.xcodeproj`, выберите схему Gas и симулятор iPhone. В **Product → Scheme → Edit Scheme → Run → Info** проверьте **Build Configuration: Debug**, затем нажмите **⌘R**.
5. В приложении откройте **Server Settings**, введите `http://IP-СЕРВЕРА:8080` без `/health`, нажмите **Save** и переходите к регистрации. Например: `http://10.12.249.108:8080`.

В актуальной регистрации есть **Choose School** и **Date of birth**. Ручное поле названия школы, выбор возраста числом и надпись «Password recovery is not available yet» означают, что запущена старая версия приложения.

Для доступа к локальному серверу в `Info.plist` уже включён `NSAllowsLocalNetworking`; глобальное отключение ATS не требуется. Публичный HTTP остаётся запрещён проверкой адреса. Описание ключа: [Apple NSAllowsLocalNetworking](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking).

## Запуск на iPhone без симулятора

1. Откройте `Gas.xcodeproj` в Xcode на Mac. Нужны SDK iOS и версия Xcode, совместимая с вашим iPhone; приложение поддерживает iOS 15+.
2. В дереве проекта выберите синий значок **Gas**, затем **TARGETS → Gas → Signing & Capabilities**. Включите автоматическую подпись, выберите свою команду и при необходимости задайте уникальный Bundle Identifier.
3. Подключите разблокированный iPhone, подтвердите доверие компьютеру и выберите телефон как устройство запуска. Если Xcode запросит Developer Mode, выполните показанные им шаги.
4. Запустите API, нажмите **Run** и настройте адрес сервера в приложении.

Установка iPhone Simulator для этого сценария не требуется. После добавления Swift-файлов перегенерируйте проект:

```sh
python3 scripts/generate_project.py
```

Настройки подписи, внесённые прямо в сгенерированный проект, могут быть перезаписаны этой командой. Не сохраняйте сертификаты или секретные ключи в Git.

## Проверка основного сценария

Достаточно одного телефона с переключением аккаунтов; несколько устройств удобнее.

1. Создайте **пять аккаунтов** с разными логинами и одной выбранной школой. Сохраните резервный код каждого аккаунта.
2. У аккаунта A установите взаимную дружбу с B, C, D и E через **Friends**. У A должны появиться четыре принятых друга.
3. Обновите **Polls**, пропустите вопрос, верните его и проголосуйте за одного из друзей. Баланс A увеличится на 20.
4. Войдите под выбранным получателем и проверьте **Inbox**: вопрос виден, отправитель не указан.
5. Перезапустите сервер и приложение: аккаунты, голос, баланс и пропуск сохраняются.
6. Проверьте смену пароля и отзыв сессии на другом устройстве, восстановление по резервному коду, жалобу и её статус, экспорт и удаление тестового аккаунта.
7. Отключите сеть после успешной синхронизации: доступны сохранённые профиль, друзья и первые 50 комплиментов; новые действия требуют сети. После выхода кэш этой сессии удаляется.

Для проверки замены вариантов на других людей создайте A больше четырёх друзей. С четырьмя друзьями кнопка **Change options** отключена.

## Автоматические проверки

```sh
python3 -m unittest discover -s server -v
python3 -m venv .venv
.venv/bin/pip install -r server/requirements.txt
.venv/bin/python scripts/smoke_http.py
```

GitHub Actions включает API-тесты, HTTP-сценарий, проверку генератора проекта и сборку iOS для симулятора. Наличие workflow не означает, что удалённая проверка уже выполнена. Xcode-сборку и ручные проверки на устройстве нужно пройти отдельно.

## Обновление старой установки

**Клиент и сервер нужно обновить вместе:** регистрация и голосования получили новые обязательные поля. Сервер автоматически мигрирует исходную схему и сохраняет рядом копию `*.pre-v2.bak`; сделайте также отдельную резервную копию перед обновлением.

Старые школьные группы сохраняются как неактивные записи `legacy-*`. Существующие пользователи остаются в своих группах; новые аккаунты туда не регистрируются. Оператор должен сопоставить эти записи настоящим школам командой `map-school`. Старый возраст не превращается в выдуманную дату рождения. При первом входе старому пользователю предлагается принять текущую информацию о приватности; резервный код он может создать в **Password & Recovery**.

- [Контракт API](docs/API.md).

Самостоятельно работающий сервер не развёрнут. Школа и дата рождения остаются заявленными пользователем: каталог не подтверждает обучение, а дата не подтверждает личность. Анонимность в малой группе не гарантирует невозможность догадаться об отправителе. APNs, фотографии профиля, SMS/email, платежи и публикация в App Store не реализованы. Локальное напоминание не сообщает о новых комплиментах.

Перед публичным пилотом нужны оператор, контакт для обращений, подходящая политика приватности, настроенное обслуживание базы и проверка на реальных устройствах. Текст в приложении описывает реализацию и не является подтверждением юридической готовности продукта.
